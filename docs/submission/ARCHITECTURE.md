# Architecture

The shared UI foundation uses locally owned [shadcn/ui components](../../src/components/ui/card.tsx), Radix interaction primitives and Tailwind4 with `@tailwindcss/postcss`. Fork Night's [visual plates](../../src/components/visual-plates.tsx) compose those primitives into room signs, paper invitations and creative task surfaces, preserving its illustrated palette and Bricolage/Inter typography. [Source license](UI-LICENSES.md).

The current application is Next.js with React and TypeScript. The [story workspace](../../src/components/fork-night.tsx) connects [social spaces](../../src/components/social-spaces.tsx), the [personal desk](../../src/components/personal-desk.tsx) and the story map through addressable hash routes. It uses browser local storage for workspace operations/drafts, social activity and each sample maker's canvas. The browser holds every sample user's data; these access rules do not provide secure private storage or synchronized collaboration.

The [domain engine](../../src/domain/engine.ts) owns ancestry, quotes, reservations, publication, discards and fixture balances. [Validation](../../src/domain/validation.ts) checks restored state. Published ancestry must form a complete, same-project seed-to-parent path. Quotes retain parent/version, fee recipients, funding account, generation cap and expiry. Duplicate transitions retain their existing result.

Integer microcredit arithmetic preserves these ledger invariants:

- Deposits equal available, reserved, spent and withdrawn amounts.
- Reserved funds equal outstanding operation holds.
- Total deposits reconcile with balances, withdrawals, generation expense and contributor claims.

Publication settles delivered generation and quoted upstream fees once; discard settles delivered generation and releases upstream fees and unused capacity. Private projects charge their group account and enforce member allowances.

[Demo pricing](../../src/domain/pricing.ts) gives new local quotes a 1-credit generation rate and a 1-credit fee for each priced ancestor. The map and quote use the same rule, including for restored rooms. Quotes record their pricing version: saved `fixture-price-v1` operations retain their original generation rates and exact fees, while new reservations use `fixture-price-v2`. A legacy quote can replay its existing reservation; it cannot start a new reservation at the old price. Restoration preserves published work, held balances, receipts and ledger entries. Credit arithmetic retains six decimal places, while whole amounts display without trailing decimals. These fictional prices do not determine provider expenses or Monad payments.

[Original openings](../../src/domain/original-project.ts) contain exactly two selected panels, no purchased ancestry and zero reuse fee. Pieces carrying inherited story context must continue that project. [Finished export](../../src/lib/finished-export.ts) embeds only the selected published path, artwork, captions and credits.

The independent [experiment runner](../../src/experiments/runner.ts) records attempts with immutable inputs and request identities, simulated expenses and artifact digests in local files. Attempt status changes as work progresses. Atomic writes and an exclusive local lock support interrupted-run recovery; uncertain dispatch does not authorize a fresh request. It does not power the browser's fixture generation or provide distributed transactions.

The [OpenAI preparation module](../../src/experiments/openai-images.ts) normalizes actual reference pixels, builds one-panel edit requests and validates returned image bytes and token usage. The separate [live experiment runner](../../src/experiments/openai-live.ts) sends sequential panel requests, carrying the original reference and saved first panel into the second call. It saves dispatch intent and raw responses before decoding; repeated execution recovers saved output without another POST. Invalid delivery cannot become a guest charge. Unknown usage remains unresolved, including on provider errors.

Its local ledger serializes all experiments, limits dispatch to ten requests within a $10 admission budget, and reserves $1 of headroom per request. Missing receipts and unknown expenses stop new dispatch. A reserve is not an OpenAI-enforced per-request billing ceiling. One real local two-panel continuation completed in 26.7 seconds of provider latency, with $0.038871 calculated from usage; the repeated attempt dispatched no additional requests. The operator's budget-transfer script disables local spending before importing that history into shared accounting.

The [public pilot migration](../../supabase/migrations/202610020001_public_pilot.sql) adds rooms, named profiles, private draft operations and published moments. Row-level policies limit guests to their own drafts and open rooms. Database functions derive the actor from Auth claims, enforce same-room ancestry, reject reuse of a request ID with different inputs, and publish a delivered operation once. Published credit snapshots the maker's display name.

The [wallet-request route](../../src/app/api/pilot/wallet-requests/route.ts) verifies the maker's bearer token and wallet signature. Its [service-only submission function](../../supabase/migrations/202610120010_wallet_requests.sql) checks ownership of a published source scene, snapshots that attribution, serializes requests per project/maker and permits one pending request. Public responses omit Auth credentials and raw signatures. Curator-signed denial closes the offchain request. Approval still requires the existing curator transaction; the server verifies the deployed runtime and maker mapping before reflecting onchain approval. [Activation and current verification limits](WALLET-REQUESTS.md).

The [generation migration](../../supabase/migrations/202610030001_generation.sql), extended by [flexible panels](../../supabase/migrations/202610040001_flexible_panels.sql), serializes budget admission across rooms and actors, reserves one allowance per requested image (one through three), and admits one durable job per operation. Each job stores its panel count; room reservations use the corresponding credit quote. Room capacity and per-guest attempts are enforced independently. Provider dispatch is recorded before a request; an existing panel intent cannot send a second POST. Unknown expenses remain reserved and pause further spending.

The [execution migration](../../supabase/migrations/202610130001_job_execution.sql) adds an atomic dispatch outbox, Production/Development fencing, run IDs, claim leases and heartbeats. Another maker can be admitted during a healthy reserved request; actual paid calls remain serialized. One maker can have one active generation across rooms. Missing usage stays unknown, and historical estimates retain liability coverage. Audited expense adjustments are append-only projections over immutable provider records. The [operator migration](../../supabase/migrations/202610130003_pilot_operations.sql) adds read-only readiness, evidence-backed legacy disposition and once-only finite rehearsal preparation. These source changes pass the isolated PostgreSQL proof; hosted activation is tracked in [the hosting guide](HOSTING.md).

The [worker](../../src/generation/run.ts) reads the full selected ancestry, sends the parent's final image as an actual reference, and adds the immediately preceding generated panel to each later request. Raw requests/responses stay in a service-only receipts bucket. Validated images become compressed WebP objects in a separate private bucket and are read back with SHA-256 verification before delivery. Only a complete selected sequence charges room credits: one for one/two panels, two for three. Earlier two-panel request inputs retain their exact wording for receipt recovery. No automatic provider retry is configured.

The [shared entrance](../../src/components/pilot-entrance.tsx) at `/pilot` offers curated stories, joined rooms and prepared-opening creation. [Room creation](../../supabase/migrations/202610130002_shared_rooms.sql) atomically saves the opening, capacity, creation receipt and creator participation under campaign limits. New rooms are public and unlisted; copying the opening transfers no funding history or release rights. Creation starts disabled.

The [room browser](../../src/components/shared-pilot.tsx) resolves explicit share links, polls a lightweight revision/credits/roster snapshot and its own private operations, and restores drafts across refresh. Story rows reload on revision changes. Visible polling refreshes on reconnect/focus and backs off on failures. Joined names are persisted participation, not live presence. [Publication notices](../../src/lib/pilot-rooms.ts) detect peer branches across the room, suppress first-load history and self-publication, and preserve the selected scene and draft. The older [visit helpers](../../src/lib/pilot-social.ts) still supply path-specific catch-up. Room invitation and exact-moment links are distinct. Draft parents remain fixed, including before sign-in.

The [saved-idea migration](../../supabase/migrations/202610030002_saved_ideas.sql) adds public-room notes with immutable author snapshots. An authenticated RPC validates the moment, derives authorship from the session, serializes the 30-idea per-guest room limit and returns the same note for identical retries. Guests cannot directly insert, edit or delete notes. A [follow-up constraint](../../supabase/migrations/202610030003_idea_whitespace.sql) rejects whitespace-only bodies. The [idea surface](../../src/components/pilot-ideas.tsx) polls bounded pages, preserves loaded notes on read failures and retains the request identity after an uncertain post response. Using an idea attaches its identity and immutable author snapshot to private work without dispatching generation.

The [composer migration](../../supabase/migrations/202610030004_composer.sql) validates a source idea against the draft's room and parent, and retains its author/body snapshot as private operation context. The [publication correction](../../supabase/migrations/202610040002_local_refills.sql) publishes the generating maker's credit without copying source-note attribution to new moments. Original notes keep their authors; existing historical snapshots are retained. The [composer](../../src/components/pilot-composer.tsx) retains original words, the variable-length preview, Undo, parent, source idea and pending shaping identity in the guest's browser. A completed helper response is replayable; changed inputs require a new request. Optional twists do not apply until selected.

The [assist server](../../src/generation/assist.ts) authenticates the guest, reads authorized story ancestry, and atomically claims a separate global/per-guest allowance before calling either provider. Cartesia returns a 60-second STT-only token for the [browser recorder](../../src/lib/ink-recorder.ts), which streams PCM to Ink-2's manual realtime endpoint and finalizes on release. The long-lived key stays on the server, and temporary tokens are neither stored in the database nor in browser storage. The application stores no audio recording; Cartesia processes the live stream under its own service policies. The 30-second capture cap is a browser control, not a provider-enforced spend ceiling. Token reuse or a modified client requires provider account controls or an enforcing relay before unattended use.

Text shaping uses a bounded structured-output request to `gpt-4.1-mini-2025-04-14`, preserves stated intent by default and validates one to three captions before replacing the preview. Every claimed request, including a failure, consumes its allowance. No provider retries automatically. The reconciler ends stale pending helper claims without replaying them; conditional completion prevents a late response overwriting an ended claim. The user's words remain editable. Image accounting stays separate.

The [generation route](../../src/app/api/pilot/generate/route.ts) verifies the bearer token and calls actor-scoped admission before attempting dispatch. The outbox survives a lost response or unavailable queue. Web and scheduled dispatch use the same globally scoped environment/operation/version key; Postgres independently prevents duplicate paid requests. **Check saved result** requests a check without revoking a worker claim. The [reconciler](../../src/generation/reconcile.ts) checks terminal run evidence before recovery, retains uncertain holds, and bounds automatic recovery to two additional executions. Its separate scheduled task is implemented with activation disabled; an eligible, attached Production minute schedule and an exercised tick are still deployment gates.

Images are fetched with the viewer's Supabase authorization and verified against their recorded digest. Storage policy permits a draft only to its maker and published output to readers of the open room. There are no public buckets or signed links bypassing these checks. Closing a room revokes future reads, but cannot revoke copies already downloaded by readers.

The [guest helper](../../src/lib/supabase/guest.ts) verifies an existing session before reusing its maker identity, or creates a new anonymous Auth user. Session errors do not silently replace an existing guest. Concurrent joins on one client share the pending operation. Database TypeScript declarations describe the source migration contracts; compare them with the actual schema at hosted cutover.

The [database proof](../../scripts/test-pilot-db.mjs) runs policies and migrations in a temporary PostgreSQL cluster with an Auth test shim. Separate sessions race request, credit, maker and campaign limits and duplicate acknowledgements. The user-run proof passes. The opt-in [hosted proof](../../scripts/test-pilot-live.ts) now uses three temporary real Auth guests to verify roster/revision visibility, session restoration, private drafts, forged-identity denial, stable attribution, concurrent once-only publication and peer continuation, then removes its own records. Delivery uses labeled service-created fixtures. The extended hosted script has not yet been run.

The original app at `/` remains a local fixture; `/pilot` uses the shared backend. The original room's [release contract](../../contracts/ForkNightReleases.sol) and [wallet module](../../src/lib/onchain/client.ts) implement curator-attested byline admission, maker-signed registration, complete-ancestry equal wallet shares, idempotent support payments and independent claims. The hackathon demo discloses this wallet-based allocation policy. Native test MON is separate from generation credits. Local EVM tests pass, and the contract is deployed on Monad testnet with MonadScan Exact Match source verification. The founder-operated browser rehearsal completed registration, release, support and all four claims; archived checker output confirms 1.0 test MON received and paid, with zero remaining liability. [Deployment, setup and limits](ONCHAIN.md).

The [local refill route](../../src/app/api/pilot/local-refill/route.ts) is explicitly enabled by `PILOT_LOCAL_CONTROLS=1` on the loopback-bound development server. It checks same-origin intent and a verified guest, then calls a service-only, idempotent database function. A refill adds five room credits, five per-guest attempts (within the schema limit), and ten image-request slots. It never resets usage, reservations, expense or the dollar ceiling, and never enables paused generation. The browser cannot call the privileged function directly. Vercel-hosted requests and non-loopback requests are rejected. This is test capacity, not sponsor revenue or a payment integration.
